# StillWatch 0.3.0 · AWS 연결 시험본

사용자 제공 Android UI에 작업자 음성 확인, OpenAI 응답 해석·연락 문안, 관리자 앱 알림, 60초 무응답 자동 문자를 통합했습니다. 2026-10-09 현재 AWS에 배포했고 연결된 SM-X930 태블릿과 ESP32로 시험했습니다. 이 문서가 현재 구현 상태의 기준이며, 기존 ZIP의 UI·서버 검증 기록은 이전 상태입니다.

## 동작

`ESP32 CSI → AWS IoT Core → 상태 판정 → 작업자 앱 질문·5초 녹음 → OpenAI 해석 → 정상 응답이면 취소 / 무응답이면 관리자 알림 → 60초 내 정상 확인이 없으면 시험 문자`

- OpenAI는 한국어 음성을 전사하고 정상 확인·도움 요청·기타 응답·불명확 응답으로 구분합니다. 애매한 답을 정상으로 확정하지 않습니다. 질문은 최대 3회이고 마감 직전에 연락 예고를 합니다.
- AI 문안은 작업자 확인 중부터 준비합니다. 주소·층·구역·출입구·회신 번호·관찰 시각을 사용합니다. 관리자의 실제 피드백과 발송 시점에 맞춰 갱신하며, API 실패 시 확인된 사실로 기본 문안을 만듭니다.
- 관리자 ‘알림 확인·현장 확인 시작’은 60초 마감을 연장하거나 발송을 취소하지 않습니다. ‘정상 확인’과 근거 입력은 아직 발송하지 않은 요청을 취소합니다. 명시적인 도움 요청은 즉시 연락을 진행합니다.
- 관리자 미지정이면 작업자 응답 마감 후 바로 시험 번호로 요청합니다. 관리자 여부는 설정에서 선택합니다.
- 같은 사건의 중복 발송을 막습니다. AWS 발송 결과가 모호하면 자동 재발송하지 않고 ‘결과 미확인’으로 표시합니다. AWS 요청 수락과 실제 수신·출동 접수를 구분합니다.
- 센서 연결/측정 불가, 휴대폰 연결 추정, 미해결 사건은 별개 상태입니다. 센서 움직임이나 연결 복구가 본인 응답을 대신하지 않습니다.

운영 시험에서는 승인받은 번호로 발송 대상을 고정했습니다. 실제 번호는 공개 사본에서 **010-0000-0000(발송 불가 예시)**으로 치환했습니다. 실제 배포 전 승인된 시험 번호를 소스와 배포 템플릿에 일관되게 설정해야 합니다. 모든 문자는 `[StillWatch 시험 · 실제 119 신고 아님]`으로 시작합니다. **실제 119 신고 연동은 구현·검증하지 않았습니다.** OpenAI는 해석과 문안 작성을 담당하고 AWS SNS가 시험 문자를 전송합니다.

## 앱 사용

APK: `releases/StillWatch-AWS-Voice-0.3.0.apk`. Android 8.0 이상용 디버그 시험본이며 스토어용 서명은 아닙니다. 태블릿에 설치한 시험 계정은 별도 사용자 계정입니다. 계정 비밀번호·세션은 `.private/`에만 있고 배포 소스/설치 파일에 포함하지 않습니다.

1. 관리자는 실제 현장 계정으로 로그인하고 **설정 → 구역**에서 주소·건물·층·구역·출입구·작업 내용을 입력합니다. **연락 대상**에서 회신 번호와 관리자 우선 확인 여부를 저장합니다. 현재 현장 정보는 `[시험] … 미등록` 값이며 실제 위치를 임의로 만들지 않았습니다.
2. **확인 시간**에서 T1(움직임 미감지)·T2(작업자 응답 대기)를 설정합니다. 시험 종료 후 현재 값은 T1 300초, T2 60초이며 관리자 대기는 60초로 고정입니다.
3. 작업자는 본인 휴대폰을 등록합니다. 관리자가 해당 구역에 지정한 뒤 작업자 앱에서 **Wi-Fi 연결 확인 켜기**와 **음성 확인 대기 시작**을 켭니다. 마이크 대기는 앱이 화면에 있을 때 처음 시작해야 합니다. 위치 권한·위치 서비스는 Wi-Fi 이름 확인에 필요합니다. 마이크·알림 권한도 허용합니다.
4. 관리자는 별도 휴대폰에서 관리자 계정으로 로그인하고 **앱 알림 대기 시작**을 켭니다. 현재 알림은 지속 서비스가 서버를 약 2초마다 확인해 표시합니다. FCM 푸시는 아직 설정되지 않았습니다.
5. 홈 화면으로 나가거나 화면을 잠가도 시작한 음성 대기는 계속됩니다. **설정의 대기 종료 / Android 강제 종료 / 전원 종료는 대기를 중단합니다.** 강제 종료 후 임의로 앱·마이크를 깨우는 기능은 없습니다. 미해결 사건의 AWS 마감과 문자 처리는 휴대폰·PC와 별도로 계속됩니다.

한 기기로 관리자와 작업자를 번갈아 시험했습니다. 실제 동시 운영에서는 각각의 계정·단말이 필요합니다. 시험 후 대기는 종료했고 태블릿은 관리자 설정을 확인할 수 있도록 준비합니다.

## 실행 환경과 API 키

PC는 개발·APK 설치·최초 ESP32 설정에 사용했습니다. 동작 중에는 ESP32와 휴대폰이 인터넷에 연결되고 AWS가 켜져 있으면 됩니다. USB 전원 대신 보조배터리나 USB 어댑터로 ESP32에 전원을 공급할 수 있습니다.

- AWS CLI 프로필: `stillwatch`, 리전: `ap-southeast-2`, 스택: `stillwatch-pilot`.
- HTTPS API: https://juypk0j08a.execute-api.ap-southeast-2.amazonaws.com (Cognito 인증 필요).
- OpenAI 키: Sydney Secrets Manager의 **`stillwatch/pilot/openai`**, JSON 키 **`apiKey`**. 이미 등록했습니다. 앱·ESP32에 OpenAI 비밀키를 넣지 않습니다.
- 모델: 음성 전사 `gpt-4o-mini-transcribe`, 응답 해석·문안 `gpt-4.1-mini`.
- ESP32: ESPectre Native 3.0.0, 장치 `7a5d2b56c99d48ed`, 내부 ping으로 CSI 입력 생성, TLS MQTT 443으로 AWS에 직접 전송. PC 트래픽 생성기가 필요하지 않습니다.
- 휴대폰은 HTTPS만 사용하며 현장 Wi-Fi와 같은 로컬 IP 대역에 있을 필요가 없습니다. 재실 추정을 켜려면 설정한 현장 SSID가 실제 연결과 일치해야 합니다.
- 현재 ESP32의 초기 Wi-Fi·MQTT 설정은 USB로 완료했습니다. 앱의 기존 ESP-IDF SoftAP 보안 1 설정 화면은 별도 지원 펌웨어용입니다. 현재 Native의 USB Improv 설정을 그 화면에서 바로 수행할 수 있다고 주장하지 않습니다.

## 재빌드·배포

JDK 17 이상, Android SDK 35, Node.js 22 이상, Python 3, AWS CLI v2가 필요합니다.

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
node --test aws/domain.test.mjs aws/flow.test.mjs aws/native.test.mjs aws/s3-sign.test.mjs
node aws/build-template.mjs
python aws/bootstrap.py
```

`bootstrap.py`는 현재 파일럿 프로필·리전·스택에 배포합니다. 첫 배포는 환경 변수 `OPENAI_API_KEY` 또는 로컬 `.private/openai-secret.json`의 `apiKey`가 필요합니다. 기존 AWS 비밀 정보가 있으면 업데이트 배포에 로컬 키가 없어도 됩니다. 장치 신규 배포에는 개인 장치 설정·자격 증명을 별도로 준비해야 합니다. `aws-config.properties`에는 API·Cognito 공개 설정만 저장하며 APK 빌드 전에 생성해야 합니다. AWS 리소스가 계속 운영 중이므로 과금은 계정에 반영됩니다.

`aws/create-test-case.py`는 개발자가 승인된 기기·번호로 연결 검증할 때 쓰는 **가상 무응답 입력**입니다. 실제 사람의 위험 상황을 검출했다는 증거가 아닙니다. `.private/`, `local.properties`, 빌드 캐시, 키·토큰을 배포 소스에 포함하지 않습니다.

## 검증한 내용과 남은 내용

- 실제 ESP32에서 약 100pps의 내부 입력·CSI 수집, idle/motion MQTT 전송과 AWS 수신을 확인했습니다. 통제된 사람 움직임 실험으로 정확도를 평가한 것은 아닙니다.
- SM-X930 / Android 16에서 홈 화면 음성 재생·마이크·OpenAI 해석을 확인했습니다. 초기 답변은 불명확으로 분류돼 마감이 유지됐습니다.
- 잠금·화면 꺼짐 상태에서 재생, 마이크 녹음(시스템 차단 없음), OpenAI `normal_confirmation`, 자동 문자 취소를 확인했습니다. 사용자가 잠금 상태의 실제 스피커 소리를 확인했습니다.
- 관리자 앱을 홈 화면으로 보낸 상태에서 현장 확인 알림을 표시했습니다. OS 알림 기록과 서버 수신 기록을 확인했습니다.
- 가상 무응답 사건에서 작업자 마감 뒤 60초 관리자 무응답으로 AWS SNS가 발송을 수락했고, 사용자가 시험 번호로 문자 도착을 확인했습니다.
- 서버 테스트 46개, Android 단위 테스트 16개, 빌드·Lint 통과(오류 0개). 단위 테스트는 실제 센서 정확도를 입증하지 않습니다.
- 공용 Wi-Fi에서 Native `ready=false`가 짧게 반복됐습니다. 그 구간은 움직임 없음으로 처리하지 않습니다. 전용 AP/핫스팟에서 현장 범위·사람 움직임·주변 장비 간섭·연속 감시를 검증해야 합니다.
- 미검증/미구현: 실제 119 연동·접수, iOS, FCM 독립 푸시, 재부팅 후 자동 대기, 장시간 배터리/Doze/통신 장애 시험, 운영용 서명·스토어 배포, 도면 자동 인식. 기존 수동 도면 편집은 유지했지만 이번 AWS 배포의 실제 업로드 시험은 별도로 남아 있습니다.

가스나 의식·호흡을 측정하지 않으며, 휴대폰 재실 추정과 Wi-Fi 움직임만으로 사고·사망을 판단하지 않습니다.
