# 디자이너 UI 통합 · 0.2.0

기준: 사용자가 제공한 `StillWatch-UI.zip`의 DESIGN, INTEGRATION, UI_CONTRACT, SCREEN_INDEX, Compose 소스와 Android 스크린샷. ZIP 내 manifest의 94개 파일 해시가 일치하고 AAR SHA256도 일치함을 확인했습니다.

디자이너의 Compose 소스를 `app/src/main/java/dev/stillwatch/ui`에 통합했습니다. 기존 앱의 Kotlin·AGP·Compose 버전과 minSdk를 유지하며 소스를 컴파일합니다. ZIP의 Kotlin 2.3 기반 AAR과 빌드 설정을 그대로 덮어쓰지 않았습니다. 원본 ZIP은 변경하지 않았습니다.

적용한 화면과 디자인:

- 관리자 홈: 작업 구역 → 미해결 사건 → 감시·연결 정보 → 최근 이벤트.
- 사건 상세: 위치와 상태 패널, 원본 시각·타임라인, AI 요약 분리, 시스템 원본 펼침, 기록 공유.
- 작업자 홈과 별도 ‘괜찮으신가요?’ 화면: 본인 응답 처리·완료 상태.
- 감시 불가, 이벤트 내역, 고정 대피 안내, 현장 도면·움직임 기록 화면.
- 현장 설정: 구역·대피·장치·연락 대상·확인 시간의 다섯 섹션.
- 디자이너의 색상·타이포그래피·간격·모서리·버튼 크기, 다크 모드, 좁은 화면·큰 글자의 정보 배치.

프로젝트 요구사항에 맞춘 조정:

- ZIP의 수동 입장·퇴장 흐름은 앱에 연결하지 않았습니다. 등록 휴대폰의 지정 Wi-Fi 연결 상태로 자동 식별하며 재실 추정을 명시합니다.
- 관리자의 알림 확인·현장 확인 결과 기록을 유지했습니다. 관리자 확인은 작업자 본인 응답을 대신하지 않습니다.
- 앱에서 실제 동작하는 PDF/이미지 도면 선택·위치/경로 편집, ESP32 프로비저닝, 휴대폰 등록·구역 지정, 알림 권한 요청을 연결했습니다.
- 별도 웹 안내의 미리보기 데이터를 실제 현장 안내로 사용하지 않습니다. 기존 앱의 관리자가 확인한 도면과 경로를 앱에서 표시합니다.
- 서버 계약이 없는 도면 자동 인식·예비 연락 대상·배터리 수치 등을 임의 구현한 것으로 표시하지 않습니다.
- 응답 완료는 실제 API 성공 또는 명시된 체험 결과에서만 표시합니다. 다른 사건의 응답 결과나 관리자 확인 결과를 현재 작업자의 응답 완료로 사용하지 않습니다.
- 과거 사건은 사건 당시 시각·휴대폰 추정 인원을 유지합니다. 센서 연결과 사건 해결 상태를 분리했습니다.

이 버전은 UI 통합이며 실제 AWS·ESP32·FCM 연결 상태는 이전 개발 버전과 동일합니다. 설치본은 체험 모드로 확인합니다. 동일한 패키지와 디버그 서명을 사용하고 versionCode를 2로 올렸습니다.

APK 빌드·검사와 에뮬레이터 결과는 `QA.md`를 참고합니다.
